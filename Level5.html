Governing Agents in Practice

Three moves. Every deployed agent needs all three.

The console above shows these in action. Here's the recipe — sourced from what ships now, not what you'd build from scratch.

01 — Stop the loop

Bound it before it starts

Set maxTurns to a realistic ceiling. Wire a SubagentStop hook to detect convergence and halt early. Add maxBudgetUsd as the financial ceiling (TypeScript SDK — the Python option is max_budget_usd; don't mix the two on one slide). Be precise about what it is: it trips when the SDK's own client-side cost estimate crosses your number — the same estimate as total_cost_usd, with documented accuracy caveats. A guardrail, not a billing-system wall; for a hard dollar cap you want a Managed Agents session budget. Without any of these, a Draft↔Verify cycle that never converges runs until it's rate-limited — the overnight-bill scenario. The enforced limit is whatever you set; there is no magic safe number.

02 — Scope each subagent

Context is not free at each step

Give each subagent its own window with only the context it needs. Pre-summarise: instead of the customer's full lifetime record, pass the last-30-days summary (~1,500 tokens vs ~50,000). Assign the minimum tool surface for the task. Over-declared tools bloat the payload (see Level 3) and widen blast radius if something goes wrong.

03 — Gate irreversible actions

Pause before anything permanent

Before any email sends, payment processes, or record mutates: pause for human approval. Use permissionMode to insert a human-in-the-loop checkpoint. Back it with a PreToolUse hook that can deny the tool call outright — not a politely-worded system prompt the model can drift past. Every approval is an audit trail entry.

Why you care

Same architecture, two reasons to fund it.

The budget & trust case

Chat users / operators

  • An ungoverned loop can burn through a budget overnight. Stop-guards turn "shocking bill" into a known ceiling.
  • A confirmation gate is your audit trail: nothing irreversible (emails, payments, record writes) happens without a logged human OK.
  • Two kinds of budget, and only one is enforced: a task budget (min 20,000 tokens) injects a countdown the model can see, so it paces itself and lands gracefully instead of being cut off — advisory. A Managed Agents session budget is dollar-denominated and platform-enforced. Task budgets prevent bad endings; session budgets prevent bad bills.
  • Agents now bill on two meters: if Anthropic runs the loop (Managed Agents) you pay tokens at standard rates plus $0.08 per session-hour, charged only while the session is running — idle time is free, and the Batch discount does not apply. Self-hosted, code execution gives each org 1,550 free container-hours/month, then $0.05/hr.

The defensive-design case

Coders / architects

  • Avoid runaway recursion and rate-limit walls: bound the loop with maxTurns and gate convergence with a SubagentStop hook.
  • Enforce read-before-write: a PreToolUse hook validates state before any mutation and can deny the call outright.
  • Give each subagent the minimum tool surface for its task — over-declaring tools both bloats the payload (see Level 3) and widens blast radius.
