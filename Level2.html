Honest small printNumbers are an illustrative model(~700-token system prompt, ~500 tokens added per turn) to make the shape of the problem visible — your real figures vary with message size. Three things worth saying out loud to a technical room: 1M is now the default window on Opus 5, Sonnet 5, Opus 4.6+ and Sonnet 4.6 — no beta header and no long-context premium (Haiku 4.5 and Sonnet 4.5 stay at 200K). Chat interfaces can manage the window on a rolling first-in-first-out basis, so a chat-specific token figure isn't a published number — don't quote one. Either way "just use the big window" doesn't save you: quality degrades before the limit, and cached tokens still occupy the window. Prompt caching cuts the dollar cost of re-sent history to roughly a tenth, but does not fix attention dilution — a cached long thread still drifts. And the failure mode is context rot (the model losing the thread of your constraints), not anything mystical. The fix is architectural: keep each working thread short, compact proactively (~50–60% full, not at the limit), and seed the next thread deliberately.
